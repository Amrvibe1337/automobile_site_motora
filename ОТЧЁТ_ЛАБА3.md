# Отчёт по лабораторной работе №3

## Тема
Подключение базы данных к веб-серверу, обработка и валидация форм, авторизация пользователей, сессии и личный кабинет.

## Цель работы
Изучить подключение базы данных к веб-серверу, освоить обработку форм регистрации, авторизации, обратной связи и поиска, реализовать личный кабинет, хранение действий пользователя в сессии и хэширование паролей.

## Выбранный стек
Выбран стек **Node.js + Express + MongoDB (Mongoose)**. Клиентская часть лабораторной работы №2 на HTML, CSS и Vanilla JavaScript сохранена и подключена к API с помощью `fetch`.

## Структура базы данных
Используются шесть прикладных коллекций: `users`, `categories`, `products`, `feedback`, `useractions`, `orders`. Сессии хранятся отдельно в `sessions` с помощью `connect-mongo`. Коллекция `favorites` и связанная функциональность удалены.

Связи между документами:

- `products.category` ссылается на `categories._id`;
- `feedback.user` ссылается на `users._id` (для гостевого обращения допускается `null`);
- `useractions.user` ссылается на `users._id`;
- `orders.user` ссылается на `users._id`, позиции заказа содержат ссылки на товары и снимки цены/названия.

MongoDB не реализует SQL `FOREIGN KEY`, поэтому связи заданы через `ObjectId` и `ref` Mongoose. Каскадное удаление обеспечено серверными маршрутами: удаление пользователя очищает его обращения, журнал действий и заказы; удаление товара обнуляет ссылки на него в сохранённых позициях заказов, не удаляя снимки названия и цены.

## Реализованные функции

1. **Подключение MongoDB.** Конфигурация через `.env`, подключение с помощью Mongoose.
2. **Хранение сессий.** `express-session` + `connect-mongo`; в сессии хранятся последние просмотры, пять последних поисковых запросов и корзина.
3. **Регистрация.** Клиентская проверка обязательных полей, email, длины пароля, повторения пароля и согласий; серверная проверка через `express-validator`; пароль хранится как bcrypt-хэш.
4. **Авторизация.** Проверка email и пароля, опция «Запомнить меня», ограничение частоты попыток входа.
5. **Обратная связь.** Валидация полей и сохранение обращения в `feedback`.
6. **Поиск.** Поиск по каталогу из MongoDB, фильтрация по категории и сортировка; длина запроса проверяется клиентом и сервером.
7. **Личный кабинет.** Просмотр/редактирование имени и email, смена пароля с проверкой старого, обращения, история заказов, история поиска (до пяти запросов), последние просмотры и журнал действий.
8. **Защита маршрутов.** Middleware проверяет наличие действующей сессии, существование и активность пользователя; админ-маршруты дополнительно проверяют роль.
9. **Журнал действий.** В `useractions` записываются вход/выход, регистрация, обновление профиля, смена пароля, отправка обращений, оформление заказов и административные изменения.
10. **Админ-панель.** CRUD автомобилей, сортировка, управление пользователями, блокировка/разблокировка, удаление и модерация обращений.

Корзина реализована через серверную сессию MongoDB. Кнопка с иконкой корзины в карточке автомобиля добавляет его в корзину; при оформлении авторизованным пользователем создаётся запись в `orders` с составом, ценой, количеством и итоговой суммой. Оплата не подключена, заказ является заявкой для подтверждения менеджером.

## Запуск

1. Установить Node.js 18+ и MongoDB (локально или Atlas).
2. Выполнить `npm install`.
3. Скопировать `.env.example` в `.env`, заполнить `MONGODB_URI` и `SESSION_SECRET`, задать `ADMIN_EMAIL` и `ADMIN_PASSWORD`.
4. Выполнить `npm run seed` для создания категорий, 15 тестовых автомобилей и учётной записи администратора.
5. Запустить `npm run dev` и открыть `http://localhost:3000`.

## Локальное хранение изображений автомобилей

Фотоматериалы каталога не загружаются со сторонних хостингов. В проект добавлены 15 локальных файлов WebP в `public/img/cars/` и локальная SVG-заглушка. В коллекции MongoDB `products` хранится только относительный публичный путь, например `/img/cars/aura-rs-v8.webp`. Express раздаёт файлы через `express.static`.

Для уже существующей базы используется команда `npm run migrate:local-images`. Скрипт проверяет наличие всех файлов и обновляет только поле `image` у автомобилей по названию; остальные данные и коллекции не затрагиваются. Админ-панель принимает только существующие пути внутри `public/img/cars/` и отклоняет внешние URL.


## Удаление старого избранного

Отдельная функциональность избранного полностью удалена: отключён API `/api/favorites`, удалены модель `Favorite` и маршрут `routes/favorites.js`, убран счётчик избранного из админ-панели. Теперь кнопка на карточке автомобиля работает только с корзиной через `/api/cart/:productId`.

Для существующей базы выполните `npm run migrate:remove-favorites`. Скрипт удаляет коллекцию `favorites` и устаревшее поле избранного из сериализованных документов коллекции `sessions`. Он не изменяет `cart`, пользователей, заказы, обращения и журнал действий. Перед запуском скрипта сервер MOTORA следует остановить. Исторические записи `favorite_add`/`favorite_remove` в `useractions` сохраняются как история старых действий.

## Дополнительные функции: заявки на автомобили и подписки

Реализованы две серверные функции на Express и MongoDB:

1. Заявки на автомобили. Форма в окне подробной информации отправляет `productId`, имя, телефон, необязательный комментарий и подтверждения ознакомления с политикой/согласия на обработку персональных данных. Сервер проверяет поля, получает актуальные название и цену автомобиля из MongoDB и создаёт документ в коллекции `requests` со статусом `pending`. В админ-панели заявки просматриваются и переводятся в статусы «Одобрена», «Отклонена» или «На рассмотрении».
2. Подписки на рассылку. Формы в нижней части страниц отправляют email на сервер. Email нормализуется и хранится в коллекции `subscribers` с уникальным индексом. Повторная отправка того же email не создаёт новый документ. Список активных подписчиков доступен администратору.

Для проверки нужно отправить тестовую заявку из карточки автомобиля, проверить документ в `requests`, изменить статус в админ-панели; затем подписаться на рассылку, повторить отправку того же email и убедиться, что количество документов в `subscribers` не увеличилось.
